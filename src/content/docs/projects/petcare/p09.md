### Punto de entrada
Retomar **el mismo PetCare de incremento P08** (core Java, `PetCareService` y colecciones según necesidades reales). No copiar el demo de ejemplos, que usa otra implementación mínima.

### Necesidad del dominio
Además de consola, una persona quiere registrar/consultar mascotas mediante una ventana gráfica. La nueva interfaz deberá reutilizar reglas ya implementadas.

### Objetivo
Construir un **adaptador gráfico mínimo** con Maven, JavaFX, FXML y Controller. Mantener CLI y core desacoplados de JavaFX. Puedes completar el incremento de forma autónoma.

### Conceptos nuevos
Maven, aplicación JavaFX, Stage/Scene, FXML, Scene Builder, Controller, controles y eventos.

### Secuencia de trabajo
1. [Preparar proyecto sin romper el core](#paso-1)
2. [Construir una vista para una necesidad real](#paso-2)
3. [Conectar Controller y servicio](#paso-3)
4. [Validar y cerrar el incremento](#paso-4)
5. [Consultar implementación de referencia](#referencia)

### Trabajo esperado
Una ventana con una operación simple (registro o búsqueda) que delegue en PetCareService. Si el servicio de cada estudiante difiere, adaptar la interacción sin rehacer el modelo.

### Evidencia
Captura, operación válida e inválida, justificación de dependencias y registro de aprendizaje. Commits sugeridos: `build: configurar adaptador JavaFX`; `feat: interfaz mínima PetCare`; `test: verificar flujo UI y negocio`.

### Fuera de alcance
No exigir TableView, FXML múltiple, navegación compleja, JSON, JDBC ni refactor completo hacia MVC.

### Checkpoint
La UI es reemplazable y la lógica del dominio sigue funcionando desde CLI.


## Paso 1


1. Ejecuta y verifica el PetCare de incremento P08 antes de modificarlo.
2. Identifica dónde viven modelo, servicio y CLI.
3. Añade una configuración Maven y dependencias JavaFX sin cambiar reglas ni colecciones.
4. Crea una clase `Application` en el paquete de UI. Conservar CLI como punto de entrada separado.
5. Muestra una ventana vacía y documenta cómo la ejecutaste.

**Checkpoint:** CLI y UI pueden arrancar, y `core` no requiere JavaFX. No generar nuevas capas vacías.


## Paso 2


1. Elige **una necesidad real de PetCare**: registrar o buscar mascota.
2. Define qué entradas y resultado necesita el usuario.
3. Diseña en Scene Builder un FXML con TextField, Button y Label.
4. Define `fx:controller`, `fx:id` y `onAction`.
5. Carga el FXML desde el punto de entrada JavaFX.

**Checkpoint:** la vista abre y expresa claramente la operación elegida; la lógica no está en XML.


## Paso 3


1. Recupera el mismo `PetCareService` que usaba tu CLI (sin clonar sus datos/reglas).
2. En el evento, lee lo que ingresó el usuario y delega en una operación del servicio.
3. Convierte el resultado o error en un mensaje de interfaz.
4. Verifica que cambiar la UI no obligaría a tocar las clases de modelo.
5. Evita duplicar listas de mascotas entre Controller y Service.

**Checkpoint:** una acción de UI utiliza efectivamente un método del core; puedes seguir ejecutando la CLI. Si tu diseño no incluye esa operación, justifica la adaptación mínima.


## Paso 4


### Pruebas
- Ejecutar arranque JavaFX.
- Registrar/buscar mascota usando el servicio existente.
- Intentar entrada inválida e inspeccionar respuesta visible.
- Confirmar que CLI sigue funcionando con el mismo core.
- Confirmar que clases del dominio no importan javafx.*.

### Evidencia
Captura o registro de ejecución, comandos reproducibles, commits y registro de aprendizaje. Explica una decisión de separación UI/core.

**Checkpoint de salida:** PetCare dispone de una primera interfaz gráfica sin reescribir reglas de integración de consola. La integración más sofisticada queda para semanas posteriores.


## Modelo y checkpoint


```text
flowchart TB
    CLI["CLI (existente)"] --> S["PetCareService"]
    FXML["Vista FXML"] --> CTRL["Controller JavaFX"]
    CTRL --> S
    S --> MODEL["Modelo / colecciones integración de consola"]
```

### Paquetes conceptuales
`core.model` y `core.service` continúan libres de `javafx.*`. `cli` y `ui` son dos formas de interacción; ninguna debe absorber reglas de negocio.

### Checklist técnico
- [ ] El core sigue compilando.
- [ ] UI JavaFX carga FXML.
- [ ] `fx:id` y `onAction` corresponden al Controller.
- [ ] Controller invoca un servicio existente.
- [ ] El servicio conserva las colecciones/validaciones de integración de consola.
- [ ] Error inválido visible y controlado.

### Evidencia
Comando Maven, captura de ejecución, prueba negativa, diagrama adaptado y commits.

### Defensa
1. ¿Qué cambiarías para usar una UI distinta?
2. ¿Qué podría seguir ejecutándose sin JavaFX?
3. ¿Por qué no guardaste la lista de mascotas dentro del Controller?
4. ¿Cómo distinguirías un error de validación de un error al cargar FXML?

### Próxima semana
Consolidar Controller/servicio y flujo de datos antes de introducir nuevas vistas o persistencia según la orientación vigente.


## Referencia


**Referencia didáctica, no solución oficial para copiar.** Adapta nombres de paquetes, contratos y constructores a tu PetCare real. La guía muestra sólo el incremento JavaFX.

### Posible estructura
```text
cl.adumun.academy.petcare
├── core/model/...            (ya existente)
├── core/service/PetCareService.java (ya existente)
├── cli/App.java              (se conserva)
└── ui/
    ├── PetCareFxApp.java
    ├── MascotaController.java
    └── mascota.fxml          (ubicado en resources)
```

### Fragmentos focalizados
```java
// El FXML apunta al Controller; el Controller delega en el servicio.
@FXML private TextField nombreField;
@FXML private Label estadoLabel;

@FXML
private void registrar() {
    try {
        // Adapta creación/identificador y método a TU contrato real.
        // petCareService.registrar(...);
        estadoLabel.setText("Operación completada");
    } catch (IllegalArgumentException ex) {
        estadoLabel.setText(ex.getMessage());
    }
}
```
Para una base runnable sin PetCare completo, estudia [el laboratorio independiente de JavaFX](https://academic-labs.adumun.cl/activities/rent-a-car-javafx-lab/).

### Decisiones propias
- Elegir registro o consulta según el servicio disponible.
- Decidir cómo compartir una instancia de Service sin crear datos duplicados.
- Escoger mensaje de éxito y manejo de error.
- Conservar toda regla de dominio donde estaba; el Controller sólo coordina presentación.

### Errores frecuentes
Crear un PetCareService nuevo en cada clic perdiendo estado; copiar colecciones al Controller; mover validaciones de negocio desde modelo a FXML; romper CLI al añadir la UI.
